# UX gap audit, 2026-10-21

Prompted by "I can't delete boards". Every route in `router.ex` was walked
for the lifecycle a person expects of what it shows: make, rename, remove
(with a confirm that says what goes and what stays), undo where it is cheap;
plus dead ends, actions without feedback, unhelpful errors, empty states,
buttons that do nothing, and buttons the role refuses.

The headline: the Boards page *had* a Remove button, and it did nothing for
a board that a bridge reads. The row went, the bridge (never told)
reported the board again within a second, and `Alnasl.Bridges.board_row/2`
made the row anew. On the hosted server every board is a bridge's board, so
there it never worked at all.

## Fixed in this pass

| Page | Gap | Severity | Fix |
|---|---|---|---|
| Boards | Remove on a bridge's board is undone by the bridge's next report | high | Remove sends `forget_board` to the bridge and the socket drops what it had queued of that board; if the bridge is offline the row goes and the page says it will return until the bridge forgets it |
| Boards | Remove does not say what happens to a board with a game in progress, or a bridge's board | medium | Three confirm texts (plain, bridge, game in progress), each saying what is kept |
| Boards | No way to rename a board | medium | "Rename" under the name; blank and over-60 refused with a reason |
| Boards | Every button crashed the page when the board had been removed in another tab (`get!`, `String.to_integer`) | medium | One lookup, "That board is no longer there." and a refresh |
| Boards | A table number that is not a number silently cleared the table | medium | Refused with "A table number is a number from 1 to 9999."; empty still clears |
| Recordings | Delete of a capture that is already gone did nothing; a failed `File.rm` was believed | low | Flash for both |
| Invitation (used) | Dead end: no way to sign in | low | Sign-in button |
| 404 / 500 | Two bare words, no way back | low | A sentence and a link to the live page |

## Checked and fine

Halls (create, rename, delete with the name typed, members out with a
confirm and the last owner kept, invitations withdrawn), bridges (add,
remove with a confirm, move), tournament codes (remove with a confirm that
says what is forgotten), placements (remove with a confirm), captures
(delete with a confirm, removed boards' captures reachable by whoever sees
everything), fair-play uploads (delete with a confirm; shares stopped by an
explicit button, reversible by sharing again), outbox (discard with a
confirm), games (set aside with a confirm; the game is kept), PIN, Lichess
key, accounts (password change, temporary password, QR sign-in).

## Needs a decision

| Page | Gap | Options |
|---|---|---|
| Everywhere a viewer can open | A viewer sees every action button; pressing one answers "Your role in this hall lets you follow the games, not change them." (`AlnaslWeb.Permit`). The refusal is clear but the button should not be there. | (a) hide/disable by role in each template (many edits, touches the pages other work is changing); (b) mark the layout read-only and disable `button`/`submit` that are not viewer-level events by a class; (c) leave it, the message is accurate |
| Games | A game cannot be removed (a PGN attached to the wrong board, a test game). It can be replaced or set aside, never deleted. | (a) "Delete this game" for owners with a typed confirm, keeping the audit log line; (b) leave: results records are not for deleting |
| Boards | Captures of a removed board are only reachable by whoever sees every hall; the hall's own arbiters lose them with the board. | (a) keep a `hall_id` beside the capture folder so the hall's owner still sees them; (b) delete captures with the board; (c) as now |
| Bridges | A bridge cannot be renamed on the server (its name is the one it brings, and its boards are named after it). | (a) server-side display name; (b) rename on the bridge only |
| Setup / Look | Theme packs can be seen and chosen but not installed or removed from the site (they are folders on the box). | (a) upload/remove in Setup, owner/admin only; (b) leave as files, documented in `docs/theme-packs.md` |
| Fair play | A tournament's analysed report cannot be deleted on demand, only by retention. | (a) "Delete this analysis" for the owner with a confirm; (b) retention only |
| Boards | Re-adding a board on the bridge, in the same connection in which it was removed here, is ignored until the link reconnects. | (a) clear the memory when the bridge reports the board absent and then present again; (b) as now (rare, a reconnect fixes it) |

## Decided afterwards (same day)

| Gap | Decision |
|---|---|
| Viewer is shown every button | Hidden by role on every page (`@may_arbiter`, `@may_owner`, `@may_admin` from `AlnaslWeb.Hall`); the server's refusals stay (defence in depth) |
| A game cannot be deleted | Built: the hall owner's "Delete this game"; refused while a connected board reads it |
| Removed boards' captures | The hall owner's (the hall is written beside the captures when the board goes); older ones stay the admin's |
| A bridge cannot be renamed | Built: owner's rename on the Bridges tab |
| Theme packs not installable from the site | Not built, by decision |
| Fair-play analysis not deletable | Built, with a frozen copy (`fair_play_snapshots`) under the report's retention and a line in the audit |
| Board put back on a bridge ignored | Fixed: the link lets it in once the bridge has reported without it |
